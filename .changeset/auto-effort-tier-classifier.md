**`rove api add --tier auto` picks the depth from your prompt** — auto effort shipped with the table (which engine and model each of `swift` / `standard` / `deep` launches) and the gate (whether that target can start), but nothing that reads the sentence you typed, so choosing a tier was always a keystroke you spent yourself. `--tier auto` hands that one question to a classifier: how much of the PROCEDURE does this prompt leave for the model to work out? Procedure given is swift, goal given but not the procedure is standard, a goal that still has to be found is deep. The classifier is a socket rather than a model — `autoEffort.classifier` takes `jev` (TypeSafe System One) or the URL of anything you host that answers `{"text"} → {"tier", "confidence"}`, which is a ten-line program — and it is **off until you set it**, because switching it on sends the first message of your task to a third party that is not the engine vendor you picked. That sentence is in `docs/CONFIGURATION.md` next to the setting rather than behind it. Nothing about this can fail a create: no key, no network, a timeout, a malformed answer, a confidence under `autoEffort.classifierThreshold`, or a tier this machine cannot start all create the task with the fields it would have had anyway and report what happened in `.tierAuto`. A pick below the threshold is dropped on purpose — a wrong pre-fill costs more than none, since someone has to notice it before they can undo it. — [@Sma1lboy](https://github.com/Sma1lboy)
