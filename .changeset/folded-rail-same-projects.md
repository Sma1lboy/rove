The folded task rail now shows exactly the projects the expanded tree shows. Folded and unfolded were deriving their sections from two different places: the tree built them with `buildTreeRows`, which hides a project you have closed down to nothing and files a repo's tasks under one header however the store interleaved them, while the rail walked the raw task list and started a new section whenever the key changed between neighbouring rows. Four things fell out of that. A repo closed down to its main checkout with the last tab shut kept a divider in the fold after the tree had dropped it. One project could fold to two dividers, which is the ordinary case rather than an exotic one, because `tasks.json` orders by creation and two repos worked on in turn arrive interleaved. A scratch session sat wherever the store had put it instead of on the bench at the top. And a task whose deletion was already in flight still held a row. Selection, grouping and order are now one shared answer that both surfaces read, so the fold cannot invent a list of its own; a section's letter also comes from the header the tree prints, which means two repos with the same basename fold to different letters (`work/api` and `oss/api` give `w──` and `o──`, not `a──` twice) instead of reading as one repo.

Folding the rail also stopped killing the `ctrl+<digit>` task jump, and the digit now means the same thing in both states. The chord was registered inside the expanded tree, which folding unmounts, so the default fold printed a jump digit on every row while the keys did nothing at all — the one thing a folded row is supposed to still be actionable by. Underneath that was the reason it could happen: the digit counted each surface's rendered ROWS, and the two surfaces do not draw the same rows, so the same number named a different session once you folded. It now counts tasks, taken from the same grouping both surfaces read, and each one prints the number on whichever row stands for that task.

Three things follow. A digit no longer reaches a specific tab — `ctrl+3` on a task with two tabs used to open its first tab and now opens the second task; tabs are still reached with `ctrl+[` / `ctrl+]` and by walking the tree. Routine sessions take no digit and, in the fold, no row at all: there are as many of them as their schedule has fired, and a daily one would have made the folded rail the longer of the two surfaces while pushing the tasks you opened yourself past the ninth slot, the last one with a digit. And the narrow layout's "↩ recent" row stopped eating a slot it never printed, which had left every row below it answering to a number one higher than it showed.
