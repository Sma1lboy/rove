**Auto effort is now auto routing, and `rove api add --tier auto` picks the depth from your prompt.** The feature never made a model try harder — it picks WHICH model a task's depth runs on, and "effort" is one of the three fields it fills, so the old name described a sibling of its own output. Everything is renamed: the Settings section (now **Auto routing**, with its description rewritten around routing rather than the old sentence with a new noun), the `state.json` keys, the docs. **Your existing settings are moved for you.** `autoEffort.<tier>.engine|model|effort` shipped in v0.9.207 and the CHANGELOG told you to hand-edit them, so the first launch after upgrading moves them to `autoRouting.<tier>.*` and removes the old names — a table you had retargeted keeps launching exactly what it launched before, and there is nothing to do by hand. (A reader that simply stopped looking at the old names would have read a retargeted tier as "no engine" and switched the feature off with nothing printed.) The new half is `--tier auto`, which hands one question to a classifier — how much of the PROCEDURE does this prompt leave for the model to work out? Procedure given is swift, goal given but not the procedure is standard, a goal that still has to be found is deep. The classifier is a socket rather than a model: `autoRouting.classifier` takes `jev` (TypeSafe System One) or the URL of anything you host that answers `{"text"} → {"tier", "confidence"}`, which is a ten-line program, and plain `http://` is accepted for a loopback address so "run it yourself and nothing leaves the machine" stays a real option. It is **off until you set it**, because switching it on sends the first message of your task to a third party that is not the engine vendor you picked — and that sentence is on screen in **Settings → Auto routing** in every mode, including off, rather than behind the switch. That section now configures the whole thing: which classifier answers, the endpoint for your own, the confidence floor, and the API key, which is stored in `~/.rove/secrets.json` (owner-only, never `state.json`, never shown back to you beyond its last four characters) rather than anywhere a bug report would carry it. Nothing about this can fail a create: no key, no network, a timeout, a malformed answer, a confidence under `autoRouting.classifierThreshold`, or a tier this machine cannot start all create the task with the fields it would have had anyway and report what happened in `.tierAuto`. `docs/ENGINES.md` has a recording of one fan-out of four routed this way — nobody chose a depth, and all four siblings launched on the row the classifier named. The judgement it sends is the one that was measured — 73.0% on 94 human-labelled prompts against a 48.9% floor, deep recall 17/20 — and it is generated from `docs/design/auto-routing/` rather than written in code, so the text a reviewer reads is the text on the wire. — [@Sma1lboy](https://github.com/Sma1lboy), [@ZHallen122](https://github.com/ZHallen122)
