**Settings → Auto effort now carries the tier classifier — including somewhere to put the API key — and says where your prompt goes before you switch it on** — the classifier landed as config keys you had to find in `state.json` plus an environment variable, which is a poor arrangement twice over: `state.json` is a bad place to keep a decision about sending your task's first message to someone who is not the engine vendor you picked, and an environment variable is something a long-lived TUI can never be handed after it started. The section now has four rows under the depth table — Classifier (`off` / `jev` / `custom`), Endpoint, the confidence floor below which no depth is pre-filled, and API key — and the sentence naming the third party sits **above** them, on screen in every mode including off, because the moment it can change your mind is before you flip the switch and not after. The key goes to a new `~/.rove/secrets.json`, owner-only and deliberately not beside your settings: `state.json` is the file `rove config` opens and people paste whole into bug reports, and a live key has no business travelling with it. A `TYPESAFE_API_KEY` exported in your shell still wins over a stored one, and the row says so by name, so pasting a key while an export is live cannot leave you watching it have no effect with nothing to blame. Settings shows the last four characters of a stored key and never the key itself; submitting the field empty clears it. When the classifier is on with no key in either place, the section says that too — that state is indistinguishable from a working one from the outside, since the only symptom is depths that never fill themselves in. — [@Sma1lboy](https://github.com/Sma1lboy)
