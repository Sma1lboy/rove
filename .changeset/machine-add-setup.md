`rove machine add` works against current Rove again and gets further on its own. On recent nightlies `rove daemon status` refused the `--json` flag that `machine add` sends, so registering a machine running one failed with `bad option "--json"`; it is accepted again. Starting a daemon on the machine no longer hangs for a minute: it is started detached (`rove daemon restart`) instead of in the foreground of the ssh session. A Rove that the machine's non-interactive PATH cannot see (common with bun and nvm installs) is found through the login shell or the usual install directories and remembered, instead of reporting "Rove is not installed". On a first connection `add` shows the host key fingerprints and asks before trusting them. A failed ssh now says which failure it was and what to do: unknown name, refused, timed out, key rejected, host key not trusted, or host key changed. `rove api` also restarts a machine's daemon that went idle instead of reporting the machine unreachable.
