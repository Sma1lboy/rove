The agent multiplexer in your shell

Rove is a terminal UI for running many AI coding agents at once. Every attempt gets its own git worktree and its own branch, so two agents working the same prompt can never write the same file.

macOS · Linux · Windows — ships its own Bun runtime. Needs git and one engine CLI on PATH.

Note 1 — General assembly Fig. 1

One prompt becomes one or more Tasks. A Task is the unit Rove isolates: it creates a git worktree, cuts a branch, and opens terminal tabs inside it. Nothing is shared sideways, so a second agent on the same prompt is working in a different directory on a different branch.

Inside a Task you can open more tabs — a second agent on the same files with its own conversation — and splits, which only divide the screen.

Project-main tasks reuse a saved checkout and directory tasks reuse a directory you own; neither is supplied with items 1 and 2.

  1. All three parts are created when the task is made. Nothing is allocated later.
  2. Losing branches are not deleted. They stay on disk after the winner is landed.
  3. Quitting the TUI detaches; it does not stop the parts. See Note 4.

Note 2 — Isolation Fig. 2

Isolation drops one notch at each level down, and the product says so in three lines:

new Task   → own worktree + own branch     (parallel work can't collide)
new Tab    → own conversation, SAME files  (a helper in the same checkout)
new Split  → same screen, one tab divided  (a monitor beside the work)

That is the whole mental model. If two agents must not touch each other's files, give them two Tasks. If one agent should read what another just wrote, give it a Tab.

Note 3 — Fan out, fan in Fig. 3

One round of that command measures as 5 attempts5 worktrees5 branches.

rove api add --repo "$PWD" \
  --agents claude:2,codex:2,copilot:1 \
  --prompt "Try independent approaches to
           simplify the auth flow."

Each sibling gets its own worktree and branch. When the round is done, rove api collect --group <id> reads the whole round's health in one call — per-task branch, diff size, checks, and the worker's own report — and rove api land --task-id <id> merges the winner. The losing branches stay on disk.

Agents talk to each other as peers. A worker spawned from another task reports home with a bare rove api send --prompt "succeeded: … (branch fix/auth-flow)". Rove recorded who spawned whom, so the reply routes back to the exact tab. There is no coordinator process.

Note 4 — Continuous operation Fig. 4

The engines run in PTYs hosted by the daemon, not by your terminal. Quitting the TUI only detaches. Drop the SSH connection, close the lid, reboot — the work keeps going, and the screens come back on attach with up to 64 MB of scrollback restored, newest first.

Machines. rove machine add narwhal registers another computer. Its tasks appear in the same sidebar under a row of their own — no ports opened, no new auth, SSH just forwards the remote daemon's unix socket. Every machine is connected at once.

Routines. A cron rule, a prompt, and a repo, owned by the daemon. Every firing creates a real task in the sidebar with its own worktree and branch — work you can open, read, disagree with, and keep talking to. Not a hidden background job.

Inbox. One list answering what needs me? Blocked items first — permission prompt, rate limit, error, dead engine — then plain finished turns. F7 jumps to the oldest blocked one across every project.

Note 5 — Symbol legend Sidebar status marks

▴Pinned — kept at the top of the list
+4 −1Changed / deleted files in the worktree
↑2 ↓1Commits ahead of / behind base
✓ ✗ ≠PR checks passing / failing / conflicted
◷Rate limited — the engine is waiting on quota
†Engine exited — the process is gone
?Needs input — it is asking you something
●Running — a turn is in flight

These are the real glyphs the sidebar draws. They are the reason the TUI stays one screen: the state of every task on every machine is legible at a glance, in a column about twelve characters wide.

Four of them — ?, ◷, †, and a failed check — are what the Inbox sorts to the top. Those are the ones that stop being work and start being your work.

Claude Code is the default. There is no in-app model picker, deliberately: you pick the model the way that engine already does, on its own launch command. Rove's job is the worktree, the branch, the tabs, and the state marks — not a second settings screen for someone else's CLI.

A mixed fleet in one round is the point of the schedule. --agents claude:2,codex:2,copilot:1 is five attempts at one prompt from three different vendors, each in its own checkout, compared side by side in one collect call.
